## Git 推送排查（xjh 远程 = github.com/xjhyonier/dashboard）
- 现象:用户说"以前能推,现在不行"。远程 xjh 指向 https://github.com/xjhyonier/dashboard.git（另有 xjh-ssh 用 git@github.com）。
- 排查:
  - 代理 127.0.0.1:7897 实际在运行（curl 返回 400 是代理自身拒绝，说明端口存活；git CONNECT 隧道可建到 github.com:443）。
  - Windows 凭据管理器确有缓存 `LegacyGeneric:target=git:https://github.com`，用户 xjhyonier。
  - workbuddy 自带 GCM（~/.workbuddy/.../git-credential-manager.exe）`get` 返回 EXIT=5（读不出）；系统版 GCM（C:\Program Files\Git）在 workbuddy bash 下 segfault，push 时同样取不到凭据 → git 回退 /dev/tty 交互输入失败。
  - 改用 PowerShell + CredRead 直接取出该凭据（user=xjhyonier, 80 字符 token），以 `https://user:token@...` 推送，仍被 GitHub 拒绝：`Invalid username or token. Password authentication is not supported for Git operations.`
- 结论:**缓存凭据已失效**（GitHub 密码登录早已禁用；或 token 过期/撤销）。这就是"以前能推现在不行"的根因。GCM 在无头环境无法刷新 OAuth。
- 解决路径(待用户):① 提供新的 GitHub PAT（含 repo 权限）一次性推送；② 或用户在自己终端跑 `git push xjh master` 触发 GCM 浏览器重新登录。临时改动已还原（local credential.helper 已 unset，仓库配置干净）。
- **结果**:用户生成了新的 classic PAT 并给出,用 `https://xjhyonier:<PAT>@github.com/xjhyonier/dashboard.git` 经系统 git(`C:\Program Files\Git\cmd\git.exe` + `-c credential.helper=`)推送成功,`27ae299..e1896f8 master -> master`,PUSH_EXIT=0。token 已用完即弃未落盘。
- **经验**:workbuddy 自带 GCM 读不出 wincred 凭据、系统 GCM 在 msys 下 segfault;在无头 agent 里推送 GitHub 的最稳路径 = 让用户提供 PAT,用「系统 git + URL 内嵌 token + 关闭 credential.helper」一次推送。后续若用户想让 `git push xjh master` 在自己终端免密,需在他们终端跑一次完成 GCM 登录(会刷新 wincred 里的失效凭据)。
- **用户已保存 token 到 ~/.workbuddy/MEMORY.md**,以后推送直接取用。
